Linux · 进程基础

程序、进程、信号与 /proc

程序是磁盘上的文件；进程是内核把程序加载并运行后创建的实例；/proc 是观察这些运行实例和内核状态的窗口。

一、程序与进程

程序是静态文件

例如 /bin/ls、/usr/bin/bash 或 ./app，保存着可执行指令。

进程是动态实例

程序执行后，内核为它建立运行状态、内存空间和资源记录。

程序文件本身不会持续占用 CPU。执行程序后，内核创建进程，进程通常拥有：

  • 进程编号和 CPU 执行状态；
  • 独立的虚拟内存空间；
  • 打开的文件、当前工作目录和环境变量；
  • 运行用户、组及相应权限。
# 同一个程序可以启动多个进程实例
./app &
./app &
./app &
程序文件 ./app
→
进程 1001
进程 1002
进程 1003
程序和进程的生命周期不同

进程结束后，程序文件通常仍在磁盘上；删除程序文件也不一定立即终止已经加载并运行的进程。

二、PID 与 PPID

PID（Process ID）是内核分配给进程的编号，在同一时刻唯一。进程退出后，其 PID 将来可能被其他进程重复使用。

PPID（Parent Process ID）是父进程的 PID。在 Bash 中执行 ./app 时，Bash 通常是 app 的父进程。

# 当前 shell 的 PID
echo $$

# 同时查看 PID、PPID、状态和命令
ps -o pid,ppid,state,cmd
  PID  PPID S CMD
 2000  1500 S bash
 2100  2000 R ./app
PID 与作业编号不是一回事

PID 由内核管理；%1 这样的作业编号由当前 Shell 管理，只在该 Shell 会话中有意义。

三、进程状态 R / S / D / T / Z

R运行或可运行
S可中断睡眠
D不可中断睡眠
T暂停或跟踪
Z僵尸
状态含义需要记住的细节
RRunning / Runnable正在使用 CPU，或者已经就绪并等待 CPU；不一定此刻正在执行。
SInterruptible Sleep等待输入、网络数据、定时器等事件，可以被信号唤醒；非常常见。
DUninterruptible Sleep通常在等待内核 I/O。信号要等它从内核等待中返回后才能生效。
TStopped / Traced被暂停或被调试器跟踪，Ctrl+Z 可使前台进程进入暂停状态。
ZZombie已经结束，但父进程尚未读取退出状态，只剩进程表记录。
 
ps -o pid,ppid,state,cmd
D 状态不一定能被 kill -9 立即清除

SIGKILL 已经处于等待状态，但进程必须先从不可中断的内核操作返回，内核才能完成终止。

不能再次“杀死”僵尸进程

Z 进程已经结束。应由父进程调用 wait() 回收退出状态，或者处理行为异常的父进程。

四、前台、后台与作业控制

前台作业

直接运行的命令通常成为终端的前台作业，可以读取终端输入：

sleep 100
  • Ctrl+C：通常向前台进程组发送 SIGINT，请求中断。
  • Ctrl+Z：通常发送 SIGTSTP，暂停前台作业。

后台作业

命令末尾加 &，Shell 会立即返回提示符，命令则在后台运行：

sleep 100 &

后台作业通常不能直接读取终端输入，否则可能被 Shell 暂停。

常用作业控制命令

jobs          # 查看当前 Shell 的作业
fg %2         # 把作业 2 放到前台继续
bg %2         # 让作业 2 在后台继续
kill %1       # 向作业 1 发送信号
后台运行不等于脱离终端

终端关闭后，普通后台进程不一定继续运行。临时需求可使用 nohup，长期服务通常应交给 systemd 管理。

nohup command >output.log 2>&1 &

五、SIGTERM 与 SIGKILL

kill 命令的本质是发送信号，并非固定执行强制终止。

SIGTERM（15）：请求正常退出

进程可以捕获、处理或忽略它，并有机会保存数据、关闭文件和释放资源。

SIGKILL（9）：强制终止

不能被捕获、忽略或阻塞，进程没有机会执行自己的清理代码。

# 默认发送 SIGTERM
kill PID
kill -TERM PID
kill -15 PID

# 强制终止
kill -KILL PID
kill -9 PID
先发送 SIGTERM
→
等待进程清理退出
→
仍无响应时考虑 SIGKILL
SIGKILL 是最后手段

它可能造成数据未写完、事务中断或临时文件残留。内核会回收进程资源，但不会替程序完成业务层清理。

六、/proc 是内核运行时视图

/proc 通常是内核提供的虚拟文件系统。它不是磁盘上的普通文件集合，而是把进程和内核的实时状态表示成目录与文件。

# 数字目录对应进程 PID
/proc/1/
/proc/1234/

# 查看指定进程
cat /proc/1234/status
tr '\0' ' ' </proc/1234/cmdline
readlink /proc/1234/exe
readlink /proc/1234/cwd
ls -l /proc/1234/fd
路径内容
/proc/PID/status进程状态、PID、PPID、内存等摘要信息
/proc/PID/cmdline启动进程时的命令行参数，以空字节分隔
/proc/PID/exe指向进程对应可执行文件的符号链接
/proc/PID/cwd指向进程当前工作目录的符号链接
/proc/PID/fd/进程已经打开的文件描述符
/proc/self指向当前访问 /proc 的进程
 
# 当前 Shell 对应的进程目录
ls -l /proc/$$

# 系统级运行信息
cat /proc/cpuinfo
cat /proc/meminfo
cat /proc/loadavg
cat /proc/uptime
读取时由内核生成

/proc 内容随系统实时变化。进程退出后，其 /proc/PID 目录随即消失；某些信息还会受到用户权限和安全配置限制。

谨慎修改 /proc/sys

/proc/sys 中的部分文件可用于调整内核参数，写入会影响正在运行的系统，不应当把它们当成普通文本文件随意修改。

七、速记总结

  • 程序是静态文件，进程是程序的一次动态运行实例。
  • PID 标识进程，PPID 指向创建它的父进程。
  • R/S/D/T/Z 分别表示可运行、可中断睡眠、不可中断睡眠、暂停和僵尸。
  • 作业编号属于当前 Shell，PID 属于操作系统内核。
  • 优先使用 SIGTERM，必要时才使用 SIGKILL。
  • /proc 是内核状态的实时视图，不是普通磁盘目录。
