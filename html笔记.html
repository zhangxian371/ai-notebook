前端学习笔记：HTML 与 HTTP 理解

1. HTML 出现的背景与目的

HTML（HyperText Markup Language）出现，最初是为了解决互联网环境下文档共享和信息关联的问题：

  • 跨平台文档共享：不同操作系统和软件文档格式各异，HTML 提供统一格式。
  • 超文本信息关联：HTML 通过超链接让文档之间建立联系，消除信息孤岛。
  • 信息标准化与结构化：用标签标记标题、列表、段落等，让浏览器和程序都能理解。
  • 构建 Web 基础：结合 HTTP 与 URL，实现全球信息共享。

2. HTML 主要解决的几个问题

2.1 文档结构表达问题

<h1>标题</h1>
<p>正文内容</p>
<ul>
  <li>项目1</li>
  <li>项目2</li>
</ul>

对应 Markdown 简化写法：

# 标题
这是正文
- 项目1
- 项目2

本质：HTML 和 Markdown 都是 Markup Language，给普通文本加上结构信息。

2.2 文档之间跳转（超文本）

<a href="network.html">计算机网络</a>

HTML 让文档可以引用文档，这是 HyperText 的核心。

2.3 跨平台显示

HTML 内容与表现分离，只标记结构，由浏览器决定显示样式，保证同一文档在不同设备上显示一致。

2.4 网络文档发布

HTML 与 URL、HTTP 配合，实现：

URL -> 定位资源
HTTP -> 请求资源
HTML -> 展示内容

3. HTTP 核心概念

3.1 HTTP 要解决的问题

HTTP 是客户端和服务器之间的统一通信协议，解决：

  • 如何表示“请求首页”“请求图片”“提交表单”“文件不存在”等
  • 统一客户端与服务器的请求与响应规则

3.2 HTTP 本质

客户端发送请求，服务器返回资源或状态：

浏览器: 我要这个资源
服务器: 给你 / 没有 / 权限不足

3.3 HTTP 请求示例

GET / HTTP/1.1
Host: example.com

HTTP/1.1 200 OK
<html> ... </html>

3.4 Resource 思想

HTTP 不关心内容类型，只关心 资源，例如：

/logo.png
/user/123
/article/abc
/video/xyz

3.5 GET 与 POST

  • GET：获取资源，不修改服务器数据，可重复执行。
  • POST：提交数据，由服务器处理，例如登录、发帖、上传文件。

3.6 状态码示例

  • 200 OK - 成功
  • 404 Not Found - 资源不存在
  • 403 Forbidden - 禁止访问
  • 500 Internal Server Error - 服务器内部错误

3.7 无状态设计

每次请求独立处理，服务器默认不知道请求是否来自同一用户。状态管理通过 Cookie、Session、Token、JWT 实现。

4. HTML + HTTP + URL 的实践价值

利用 GitHub Pages 发布 AI 对话或笔记，本质上是在使用 Web 的原始优势：公开资源天然可寻址。

URL
↓
HTTP GET
↓
HTML

优点：

  • 简单：无需数据库，只要 HTML/CSS/JS
  • 稳定：多年前 HTML 现在仍可打开
  • 可迁移：复制文件即可迁移到其他静态站
  • URL 天然索引：地址、标识符、分类三合一

对比网盘、云文档，静态站省去登录、客户端和同步流程，更符合 Web 最初设计精神。

5. 总结知识主线

用户输入网址
        │
        ▼
      URL -> 定位资源
        │
        ▼
      HTTP -> 获取资源
        │
        ▼
  HTML / JSON / 图片 -> 浏览器解析展示

HTML 解决：
信息如何组织和关联

URL 解决：
信息在哪里

HTTP 解决：
信息如何获取

理解这一条主线，你的前端学习、静态站实践和 AI 内容管理都会不断回到这条底层逻辑。
